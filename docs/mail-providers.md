# חיבור חשבון לשליחת מיילים

הכניסה לאתר וחיבור תיבה לשליחת מיילים הן הרשאות נפרדות. מנהל נכנס אל `/admin/email`, בוחר Gmail או Outlook, מאשר הרשאה באתר הספק ושולח הודעת בדיקה. הרשאה לא תקינה או אישור שבוטל אינם מחליפים את החשבון הקודם. ניתוק מפסיק שליחה דרך שני הספקים. אין סיסמת מנהל מובנית; יצירת המנהל הראשון מתוארת ב־`database-integrity.md`.

## Gmail

יש לשמור את פרטי לקוח OAuth בהגדרות `Gmail` הקיימות, ולהגדיר כתובת החזרה מסוג Web:

```
http://localhost:8081/api/email/gmail/callback
```

להתחברות המשתמשים עם Google יש לאשר בנפרד את `http://localhost:8081` תחת `Authorized JavaScript origins`. אם הפורט המקומי השתנה, יש לעדכן את הגדרות הספק. אין לשלוח סודות בדפדפן או לשמור אותם ב־Git.

`EMAIL_RECONNECT_REQUIRED` פירושו שהרשאת השליחה דורשת חיבור מחדש. לאחר החיבור ושליחת בדיקה ניתן לבקש מייל אימות חדש. כישלון בהרשמה אינו מוחק את החשבון; כישלון בבקשת שליחה חוזרת מחזיר שגיאה ואינו מציג הצלחה.

## Outlook / Microsoft 365

יש לרשום אפליקציה ב־Microsoft Entra, לבחור סוגי חשבונות מתאימים וליצור סוד לקוח בצד השרת בלבד. לחשבונות אישיים וארגוניים יחד יש לבחור אפשרות התומכת בשניהם. הרשאות Delegated: `Mail.Send`, `User.Read`, וכן `offline_access`. אין בקשת גישה לקריאת תוכן תיבת הדואר.

בהגדרות `domix-server/.env` המקומי, שאינו נכלל ב־Git:

```
Outlook__ClientId=<application-client-id>
Outlook__ClientSecret=<client-secret-value>
Outlook__TenantId=common
```

אפשר לבחור `organizations`, `consumers` או מזהה tenant מסוג GUID לפי מדיניות הארגון. יש להוסיף פלטפורמת Web עם כתובת החזרה המדויקת:

```
http://localhost:8081/api/email/outlook/callback
```

אפשר להגדיר `Outlook__RedirectUri` במפורש. בסביבת פריסה משתמשים בכתובת HTTPS של האתר. לאחר שינוי משתנים יש ליצור מחדש את שירות הנתונים באמצעות סקריפט ההפעלה. מדיניות של ארגון Microsoft 365 עשויה לדרוש אישור מנהל tenant. שימוש בתיבת Microsoft אינו משנה את ספק הכניסה לאתר.

האישור משתמש ב־PKCE ובמצב חד־פעמי הקשור למנהל למשך עשר דקות. בסיום נבדקת הרשאת המנהל מחדש. הרשאות נשמרות מוצפנות במסד בעזרת מנגנון ההצפנה הקיים; סודות הלקוח נשארים בהגדרות השרת. יש לשמר את `JWT_SECRET` הקיים כדי לפענח את ההרשאות. תהליך האישור משתמש בזיכרון של מופע השרת, ולכן דורש אותו מופע לאורך האישור; הפעלה מחדש מחייבת התחלה מחדש.

השליחה משתמשת ב־Microsoft Graph `/me/sendMail`. תשובת `202` היא קבלת בקשת שליחה אצל הספק, ואינה הוכחה שהמייל הגיע לתיבת הנמען. תוצאת שליחה עמומה אינה נשלחת שוב אוטומטית. אין שינוי באימות TLS; בסביבת נטפרי יש להשתמש בשכבת התעודות הקיימת.

## שדרוג והתאוששות

המיגרציה מוסיפה `SystemEmailSettings.Provider` עם ברירת מחדל `gmail`, כך שהגדרות Gmail קיימות נשמרות, וכן עמודת זמן אישית לניקוי התראות. אין מחיקת תיבות, משתמשים או התראות משותפות. ניקוי חלונית ההתראות מסתיר רק התראות עד הזמן האחרון שהוצג אצל אותו משתמש; הודעות חדשות נשארות.

לפני שדרוג יש לגבות ולוודא שחזור בסביבה נפרדת. לאחריו יש לבדוק מצב חשבון, שליחת בדיקה, שליחה חוזרת של אימות והפרדה בין משתמשים בניקוי התראות. חזרה לגרסת קוד קודמת דורשת תחילה לנתק Outlook ולחבר Gmail; לגרסה הקודמת אין יכולת להבחין בין הספקים. משאירים את העמודות הנוספות במסד. `Down` חסום כדי למנוע הסרת נתונים או פירוש הרשאת Microsoft כהרשאת Gmail. אין צורך למחוק volumes.

מקורות: https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow
https://learn.microsoft.com/en-us/graph/api/user-sendmail
https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid

## העדפות הודעות אישיות

בהגדרות החשבון, תחת „עדכונים על הודעות”, אפשר לבטל את שליחת המייל על הודעה ממשתמש אחר. ההודעה נשמרת ומוצגת באתר בכל מקרה; מיילי אימות ואיפוס סיסמה אינם מושפעים. ברירת המחדל משמרת את התנהגות המערכת הקיימת. ההעדפה נבדקת בשרת אצל הנמען, ולא אצל השולח.

לאחר שמירת הודעה השרת שולח אירוע ללא תוכן ההודעה, רק לקבוצת החיבורים המאומתת של הנמען. בממשק מוצגת התראה כללית וספירת הודעות שלא נקראו. חיבור מחדש מרענן את התיבה; בדיקה תקופתית של הספירה משלימה אירועים שהוחמצו. זו התראה בתוך האתר, לא הרשאת Push של מערכת ההפעלה. תוכן ההודעה אינו נשלח באירוע או בכותרת ההתראה.

המיגרציה `MessageEmailPreferences` מוסיפה עמודה עם ברירת מחדל התואמת להתנהגות הקיימת, ללא מחיקת נתונים. לפני חזרה לקוד ישן שאינו מכבד בחירה זו יש לנתק את חשבון השליחה, כדי לא לשלוח מיילים בניגוד להעדפה שנשמרה. אין להסיר את העמודה. יש לבדוק בחירה נפרדת של שני חשבונות, הודעה ללא מייל, ספירת הודעות אישית ואירוע בזמן אמת לנמען בלבד.
