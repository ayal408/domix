# החלפת דירות זמנית

לצד השכרה ומכירה ניתן לפרסם דירה להחלפה, עם עיר הדירה, עיר מבוקשת ותאריכי זמינות. במסך `/exchange` בוחרים את הדירה שמציעים, יעד ותאריכי כניסה ויציאה. ההצעות מתעדכנות אוטומטית אחרי הפסקה קצרה בהקלדה.

## כללי התאמה

- הדירה המוצעת חייבת להיות בבעלות המשתמש המחובר, במצב זמין ובסוג Exchange.
- שתי הדירות חייבות להיות זמינות במשך כל התקופה, ולא רק בחלק ממנה.
- יום היציאה אינו ליל אירוח; כניסה ויציאה באותו יום אינן תקופה תקינה.
- עיר היעד מותאמת במדויק אחרי הסרת רווחים והמרת אותיות לקטנות; אין התאמת מרחק גאוגרפי או אזורים סמוכים.
- דירות המשתמש עצמו ומודעות שהוסרו מההיצע אינן מוצעות.
- התאמות הדדיות מוצגות ראשונות: העיר שהצד השני מחפש זהה לעיר הדירה שהמשתמש מציע. תוצאות אחרות מסומנות כהתאמות יעד ותאריכים בלבד.
- הופעה בהצעות אינה אישור להחלפה. שריון נעשה רק בבקשת החלפה שאושרה בידי הצד השני. אין סליקה או הסכם משפטי אוטומטי.

## מודעות ונתונים קיימים

המיגרציה `AddTemporaryHomeExchange` מוסיפה את שדות ההחלפה והקשר בין הודעה לשתי הדירות. מודעות קיימות מסומנות `Unspecified`; אין לנחש אם הן למכירה או להשכרה. אפשר להשלים סוג עסקה בעריכת מודעה.

מספר חדרים נשמר כ־decimal, לרבות בחיפושים שמורים, כדי לאפשר 3.5 חדרים. ירידה לגרסה הקודמת עלולה לאבד חלקי חדרים ושדות החלפה — יש לגבות לפני שחזור מיגרציה. המיגרציה עולה אוטומטית בהפעלת השרת לפי המנגנון הקיים. יש לבדוק על עותק בסיס הנתונים לפני שדרוג סביבת משתמשים.

שליחת הצעת החלפה שומרת את הנכס המבוקש, הדירה המוצעת והתאריכים. השרת בודק בעלות וזמינות שוב בזמן השליחה. מזהי הנכסים בהודעות נשמרים גם אם מודעה מוסרת, כדי לשמר הקשר; הקישור עשוי להוביל לנכס שכבר אינו קיים.

## בורר תאריכים

משתמשים ב־`react-hebrew-datepicker@1.1.3`, עם לוח עברי ולועזי. הערך נשאר `YYYY-MM-DD` ונשמר כ־DateOnly, ללא המרה ל־UTC. משמעות "היום" בבקשות ההחלפה היא יום ישראל.

`patches/react-hebrew-datepicker+1.1.3.patch` מתקן את ההמרה בין היום העברי לערך ISO: מסיר קידום מלאכותי ביום, מפיק תאריך מקומי ומפענח ערך מבוקר בצהרי היום המקומי. זה מונע תלות באזור הזמן. `postinstall` מחיל את התיקון גם ב־CI וב־Docker. בשדרוג הספרייה יש לבדוק אם התיקון כבר נכלל בה ולהריץ את בדיקות הבורר לפני הסרתו.

## בדיקות

```sh
cd domix-client
npm ci
npm run typecheck
npm run lint
npm test
npm run build
TZ=Asia/Jerusalem npx vitest run src/components/ui/HebrewDateField.test.tsx
TZ=America/Los_Angeles npx vitest run src/components/ui/HebrewDateField.test.tsx
```

```sh
dotnet test domix-server.Tests
```

לבדיקה ידנית: לפרסם שתי דירות בשתי ערים עם יעדים הפוכים ותקופות חופפות; לבדוק התאמה הדדית, תקופה שמכוסה רק בחלקה, דירה של משתמש אחר, מודעה לא זמינה ופנייה שמציגה את שתי הדירות בתיבת ההודעות. לבדוק חזרה מהנכס לחיפוש, רענון כתובת וסינון מכירה/השכרה/החלפה, לרבות חיפוש שמור.

הגישה לקטלוג ולחיפוש נשארת מבוססת חשבון. פתיחת מאגר ציבורי מצריכה החלטה אילו פרטי כתובת וזהות מיועדים לפרסום.

## בקשות החלפה ויומן זמינות

ב־`/exchange/requests` מופיעות רק בקשות שהמשתמש משתתף בהן. שליחת בקשה היא אישור מצד השולח לפרטים שנבחרו; רק הצד המקבל יכול לאשר. נבדקת קיבולת האורחים בשתי הדירות. שינוי תאריכים יוצר בקשה חדשה ומחליף את הקודמת, ונדרש אישור חדש. כל פעולה כוללת גרסה כדי למנוע אישור של פרטים שכבר השתנו.

האישור נועל את שורות שתי הדירות בסדר קבוע בטרנזקציית PostgreSQL, בודק שוב זמינות ושומר את שתיהן יחד. חסימות ומחיקות משתמשות באותן נעילות. ביטול משחרר את שתי הדירות. אי אפשר למחוק דירה או חשבון עם החלפה מאושרת עתידית לפני ביטולה. מחיקה מבטלת בקשות ממתינות ומסירה תקופות והתראות מתאימות.

ב־`/exchange/calendar` מוסיפים תקופות פנויות וחסימות אישיות. תקופות פנויות מפורשות מחליפות את הזמינות הבסיסית במודעה, ותקופות רציפות מצטרפות זו לזו. יום היציאה אינו חופף לכניסה הבאה. חסימה גוברת על תקופה פנויה והחלפה מאושרת גוברת על שתיהן. כדי לשחרר החלפה מאושרת, מבטלים אותה במסך הבקשות.

## פרטי אירוח, אמון והתראות

קיבולת אורחים, מיטות נפרדות, מטבח כשר, מרחק הליכה לבית כנסת והערות שבת הם שדות רשות לפי הצהרת המארח, ללא אימות או פסיקה של המערכת. מסנן שנבחר כדרישה מסיר מודעות שבהן הפרט לא נמסר. קשר בטלפון ובהודעות באתר אינו מחייב WhatsApp.

חסימה מסתירה הצעות ומונעת פניות ובקשות חדשות, אך אינה מבטלת החלפה קיימת. דיווח נשמר בתיבת התמיכה למנהלים. ביקורת אחת לכל משתתף מתאפשרת רק לאחר תאריך היציאה ואישור השלמה משני הצדדים. דירוג המודעות הישן אינו מוצג למודעות החלפה; ביקורות ההחלפה מוצגות בנפרד בפרופיל המארח.

ההתראות כבויות כברירת מחדל. אפשר לבחור בדיקה בהקדם (כל 15 דקות כברירת מחדל), יומית או שבועית, ולכבות או למחוק ב־`/exchange/watches`. נשלחות רק הצעות חדשות למשתמש פעיל עם מייל מאומת; הרשמה אינה שולחת את המאגר הקיים. אפשר לשמור עד 20 התראות. `ExchangeAlerts:IntervalMinutes` משנה את מחזור הבדיקה. תדירות יומית ושבועית נמדדת מהמסירה האחרונה.

עובד ההתראות משתמש בגרסה ובחכירה מוגבלת בזמן כדי למנוע עיבוד רגיל כפול בכמה מופעי שרת. תקלה אחרי שהדואר כבר נמסר עלולה לגרום למסירה חוזרת בניסיון הבא; אין הבטחת זמן מסירה מדויק. ביטול אינו מחזיר הודעה שכבר נמסרה לשירות הדואר.

המיגרציה `AddExchangeAgreementsAndHospitality` מוסיפה את טבלאות הבקשות, היומן, ההתראות, החסימות והביקורות ואת שדות האירוח. אין סיווג מחדש של מודעות קיימות. יש לגבות לפני שדרוג; ירידה מהמיגרציה מוחקת את הנתונים החדשים.

בדיקת השילוב ב־CI כוללת שתי בקשות שמתחרות על דירה, אישור במקביל, ביטול ופינוי תאריכים, הרשאות, כיבוי התראה, חסימה ודיווח מול PostgreSQL אמיתי. בדיקת הדפדפן משתמשת ב־API מדומה לבדיקת תצוגה בלבד.
