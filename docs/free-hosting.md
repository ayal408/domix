# פריסה חינמית ללא אשראי וללא הירדמות

## היעד והמצב

היעד הוא Northflank Cloud במסלול Sandbox החינמי בלבד. לפי דף התמחור הרשמי שנבדק ב־26 באוקטובר 2026, המסלול כולל שני שירותים, שני jobs ובסיס נתונים אחד, ללא כרטיס וללא הירדמות. התנאים והמכסות עשויים להשתנות; יש לבדוק בחשבון עצמו שהסכום הוא אפס. אין לבחור Pay as you go, להזין אשראי או לאשר שירות בתשלום. אם נדרשת בדיקת אשראי או מוצעת הקצאה שאינה כלולה, עוצרים.

הקוד מוכן לאריזת שני שירותים. המסמך אינו אישור לפריסה שבוצעה או לזמינות חיה. נדרשים חשבון בבעלות המשתמשת, הרשאת GitHub, יצירת המשאבים ואימות כתובת האתר בפועל. אין הבטחת זמינות או קיבולת לעומס ייצור במסגרת החינמית.

## מבנה

| רכיב | הגדרה |
| --- | --- |
| שער ציבורי | `deploy/gateway.Dockerfile`, הקשר הבנייה הוא שורש המאגר. כולל React, nginx ו־Node auth בשירות אחד |
| API פרטי | `domix-server/Dockerfile`, הקשר הבנייה `domix-server/`, פורט פנימי 8080. לא לפתוח פורט ציבורי |
| בסיס נתונים | PostgreSQL 16 פרטי, במסלול Sandbox הכלול בלבד |
| תמונות | Cloudinary Image & Video API Free, ללא כרטיס. המפתחות נשארים בשרת |

רק פורט 8080 בשער ציבורי, עם HTTPS שמספק Northflank וכתובת השירות החינמית. אין צורך לקנות דומיין. דפי React, האימות, API ו־WebSocket עוברים באותו מקור כדי לשמור על עוגיות התחברות ומסלולים קיימים. תהליך nginx ותהליך auth מפוקחים יחד; כשל של אחד מסיים את השירות לצורך הפעלה מחדש.

Render החינמי אינו היעד הזה: הוא נרדם ומסד הנתונים החינמי שלו פג לאחר 30 יום. אין שימוש בפינגים כדי להסתיר מגבלת שינה.

## הכנה בחשבונות

1. להירשם ב־https://app.northflank.com/ עם GitHub ולבחור Sandbox ללא אשראי. לחבר רק את המאגר הנדרש: `ayal408/domix`.
2. לפתוח חשבון Free ב־https://cloudinary.com/users/register_free ולבחור Image & Video API. אין צורך ב־unsigned upload preset, בכרטיס או בתוסף בתשלום.
3. את Cloud name, API key ו־API secret מעבירים לשדות הסודיים של שירות ה־API בלבד. אין להדביק אותם בצ׳אט, בקוד או בארגומנטים לבנייה.

## יצירת הסביבה

1. ליצור פרויקט יחיד ואזור אחד לכל הרכיבים.
2. ליצור PostgreSQL 16 מההקצאה החינמית. לשמור אותו פרטי ולהשתמש בפרטי החיבור הפנימיים, לא בכתובת ציבורית.
3. ליצור שני שירותי Combined מהמאגר ומהענף `dev`, לאחר מיזוג שינוי הפריסה. לא להפעיל preview environments אוטומטיים שיצרכו שירותים נוספים.
4. לשער: Dockerfile `deploy/gateway.Dockerfile`, build context שורש המאגר. להגדיר פורט HTTP ציבורי 8080 ו־HTTPS מנוהל. אין לפרסם את פורט auth 5000.
5. ל־API: Dockerfile `domix-server/Dockerfile`, build context `domix-server/`. פורט 8080 פרטי בלבד. אין להעביר `TRUST_LOCAL_DEV_CA=true`.
6. לבחור רק משאבים שמוצגים ככלולים בחינם, להתחיל במופע אחד לכל שירות ולוודא שלא מופעל scale-to-zero. אם אין הקצאה מתאימה בחינם, לא ליצור שירות בתשלום כתחליף.

## משתני סביבה

`deploy/northflank.env.example` הוא דוגמה עם מצייני מקום בלבד, לא קובץ שמוכן להפעלה. משתמשים בשדות Runtime variables / secrets ב־Northflank, לא ב־build arguments עבור סודות.

- בשני השירותים: אותם `JWT_SECRET` ו־`INTERNAL_SERVICE_KEY`, שני ערכים אקראיים נפרדים בני 32 תווים לפחות. לא להחליף אותם בכל פריסה: החלפת JWT פוגעת גם ביכולת פענוח חיבור Gmail הקיים.
- ב־API: `DEFAULT_CONNECTION` בפורמט Npgsql מתוך פרטי PostgreSQL הפנימיים; `PORT=8080`, `ASPNETCORE_ENVIRONMENT=Production`, `CLIENT_APP_URL` שווה לכתובת HTTPS המדויקת של השער.
- ב־API: `RequireRemoteImageStorage=true` וכל שלושת משתני `Cloudinary__...`. במצב הזה השרת מסרב לעלות בלי הגדרת אחסון מלאה; אין נפילה שקטה לדיסק זמני.
- בשער: `DATA_SERVICE_URL=http://<API_INTERNAL_HOST>:8080`, `PORT=8080`, `NODE_ENV=production`, `COOKIE_SAME_SITE=strict`. להעתיק את שם ה־DNS הפנימי מהשירות, לא להמציא אותו.
- Google sign-in הוא רשות: כדי להפעיל, נדרשים `VITE_GOOGLE_CLIENT_ID` כארגומנט בנייה ו־`GOOGLE_CLIENT_ID` בשער, והתאמת המקור המורשה בחשבון Google. השארה ריקה משמרת כניסה בסיסמה.
- Gmail למשלוח אימות ואיפוס דורש את חיבור המייל הקיים ואת הגדרותיו. מפתחות Gmail/Gemini לדוגמה אינם חשבונות פעילים. אין להציג משלוח אימות כתקין לפני בדיקת מסירה אמיתית. אין להפעיל יכולות AI בתשלום.

השרת מחיל מיגרציות בהפעלה. זו סביבה חדשה וריקה, ואינה העתק של נתוני המחשב המקומי. העברת נתונים קיימים דורשת גיבוי והעברה מתוכננת בנפרד.

## בדיקות לפני מסירת קישור

- דף `/exchange` נפתח ב־HTTPS וגם לאחר רענון ישיר; המסלולים הפשוטים להשכרה ולהחלפה זמינים.
- `GET /api/auth/healthz` מחזיר JSON עם `status: ok`; `GET /api/health/db-query` מצליח מול PostgreSQL.
- הרשמה והתחברות בסיסמה, רענון העוגייה ויציאה פועלים בדפדפן. לבדוק שעוגיית refresh כוללת Secure ו־HttpOnly.
- פרטי חיבור פנימיים אינם נגישים בציבור, ונתיבי User הפנימיים נחסמים בשער.
- לפרסם מודעת בדיקה, להעלות תמונה, לבצע פריסה מחדש ולוודא שהמודעה והתמונה נשמרות. התמונה צריכה לקבל כתובת HTTPS ב־Cloudinary, לא `/images/...`.
- לבדוק הודעות ונוכחות ב־WebSocket ושני משתמשים שונים לפני פתיחה לקהל.
- לבדוק מכסות וזיכרון בחשבון בפועל; לא ניתן להבטיח מראש שהמסלול מספיק לכל עומס. לבדוק rate limiting דרך כתובת השירות, משום שכתובת הלקוח תלויה בנתיב הפרוקסי של ספק האירוח.
- יצירת משתמש מנהל צריכה להיעשות בהליך מורשה נפרד. אין בפריסה סיסמת מנהל קבועה או מסלול ציבורי להעלאת הרשאות.

`deploy/smoke-gateway.sh` משמש רק CI מול בסיס נתונים חד־פעמי. הוא יוצר חשבון בדיקה ואין להריצו מול סביבה חיה.

## נתונים ומכסות

העלאות Cloudinary עוברות את בדיקות סוג הקובץ, גודל ובעלות הקיימות לפני משלוח לספק. חתימת ההעלאה נוצרת בצד השרת ואין העברת API secret ללקוח. האחסון המקומי נשאר להתקנה מקומית בלבד. תמונות מקומיות ישנות אינן מועברות אוטומטית; נדרשת העברה נפרדת לפני שימוש בנתונים ישנים בענן.

אין כרגע מחיקה אוטומטית של קובצי Cloudinary בעת מחיקת מודעה/חשבון; להסרת קבצים שאינם בשימוש יש להשתמש בניהול המדיה של החשבון. יש לתכנן מדיניות מחיקה וגיבוי לפני שימוש קבוע, ולעקוב אחר מכסת התמונות והנתונים. חינם אינו אחסון בלתי מוגבל.
